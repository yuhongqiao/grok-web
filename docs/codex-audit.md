## 仍存在的已复现缺陷

### P2：正文和文本附件依靠前缀区分

`server/codex.js` 的 `replaceText()`、编辑窗口及历史渲染以 `附件：` 前缀判断文本附件。普通正文如果恰好以该前缀开头，也会被误判。

复现：发送普通消息 `附件：这是普通用户消息`，完成后编辑为 `edited ordinary message`。新分支实际输入含两段文字：新正文，以及本应替换掉的旧正文。编辑窗口初始正文和历史展示也受相同判断影响。

此问题本轮未修复。应引入可持久化的正文/附件标识，并考虑旧历史的兼容；已有无标识内容无法仅凭该前缀可靠区分。修复时需要覆盖只有附件、正文同前缀、编辑队列及从 CLI 恢复历史的情况。

## 尚未实现的能力

这些是当前网页与完整 CLI/开发工作区之间的差距，不能因基础回归通过就视为已经支持。

| 优先顺序 | 缺口 | 当前边界 |
| --- | --- | --- |
| 高 | CLI 版本和能力检测 | 主要基于本机 `0.163.0-alpha.11.2`；部分实验接口直接调用，缺少完整能力探测、兼容降级和版本矩阵 |
| 中 | 账号和 MCP 管理 | 继承本机 CLI 配置；没有网页登录/退出、MCP 服务配置和连接管理 |
| 中 | 完整审批协议 | 没有持久命令/网络规则修订、旧版审批协议、动态工具回调、设备证明等完整客户端实现；未知请求会明确拒绝 |
| 中 | 更多附件类型 | 只支持图片和 UTF-8 文本；PDF、Office、音频及其他二进制输入未接入 |
| 中 | 真正按需加载长历史 | 后端打开会话时读完全部历史分页，前端只分批展示；尚无按需网络加载和大型会话压力验证 |
| 后续 | CLI 原生消息队列对接 | 当前使用网页服务自己的持久队列；退出时发送结果不确定的消息仍需核对历史，不能保证自动恢复时只执行一次 |
| 后续 | 旧版历史迁移 | 旧版历史原地回退不支持，只能通过编辑/重试分支继续；没有自动迁移 |

历史回退和分叉只操作对话，不恢复项目文件。文件版本恢复不是现有按钮的能力。
